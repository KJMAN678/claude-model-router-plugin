# model-router: 作業の振り分け

ユーザーのメッセージを受けたら、作業を始める前に **1 回だけ** 次の手順で判定する。

1. 依頼の種類を決める: 設計・調査 / 実装 / レビュー。
2. 難易度の段階（1 が最も軽い）を決める。
3. 下の表から、実行方法を選ぶ。
4. 判定結果を 1 行で表示する。書式は `→ <モデル> / <effort>（<種類> <段階>）`。メインで実行するときは `→ メインで実行（実装 1）`。
5. 表のセルが `メインで実行` なら、そのまま自分で作業する。それ以外なら、Agent ツールを `subagent_type: general-purpose`、セルの `model` と `effort`、下の「依頼文」で呼ぶ。

## 表

| 種類 | 1 | 2 | 3 | 4 |
|--|--|--|--|--|
| 設計・調査 | opus / medium | opus / high | fable / high | fable / xhigh |
| 実装 | メインで実行 | opus / high | opus / xhigh | — |
| レビュー | opus / xhigh | fable / xhigh | — | — |

`opus / high` は Agent ツールの `model: opus`、`effort: high`。

## 難易度の判定基準

- 軽い側: 対象が 1〜2 ファイル、既存のパターンを踏襲する、答えがほぼ 1 つに決まる。
- 重い側: 複数のコンポーネントにまたがる、トレードオフを比べる必要がある、未知の領域、並行処理・セキュリティ・データ移行が絡む。
- 迷ったら 1 段重い側を選ぶ。

## ルール

1. 雑談や短い質問など、表のどれにも当てはまらないものは、subagent を使わずにそのまま答える。
2. ユーザーがモデルや effort を明示した場合（「Fable で」「もっと重く」など）は、その指定を優先する。
3. 「続けて」「そこを直して」など、直前に subagent に任せた作業の続きは、同じ種類と段階を引き継ぐ。SendMessage が使えるなら同じ subagent に送り、使えなければ新しく Agent ツールを呼ぶ（直前の結果の要点も依頼文に入れる）。
4. subagent の作業中は、同じ作業をメインでしない。結果が返ったら、ユーザーに伝える。
5. 自分が Sonnet でない場合は、最初の 1 回だけ「メインのモデルは `/model sonnet` を勧めます」と伝える。振り分けはそのまま続ける。

## 依頼文（subagent はこの会話を読めない）

Agent ツールの `prompt` に、次を書く。

- ユーザーの依頼（原文のまま）
- 会話の中で決まったこと、制約、関係するファイルのパス
- 何を返してほしいか（設計・調査は結論と理由、実装は変更したファイルと確認結果、レビューは指摘の一覧）
- ユーザーに確かめないと決められないことが出たら、作業を止めて質問として返すこと（subagent はユーザーに直接質問できない）
