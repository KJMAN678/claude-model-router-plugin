# 削減額の確認機能 設計

- 日付: 2026-11-16
- 対象: `hooks/register.ts`（mod）

## 目的

model-router を使い続けるかを判断するため、実際の利用（ターンごとに切り替えたモデル）と、基準のモデル（例: Opus 5.5）だけで動かした場合を比べ、トークンと料金の差を示す。判断に使うので、削減額は**控えめに**出す（甘く見積もらない）。

- 対象外: effort の差の推定（基準を medium にしても、考える量の減り方は観測できない）、過去のセッションの集計、グラフ表示。

## 方式（決めたこと）

A 案: mod の中で、リクエストごとの利用量を記録し、基準の単価で計算し直す。セッションをまたいで累計し、コマンドで表示する。

- B 案（セッション記録を読むスクリプト）は、分類の Haiku 費用が記録に残らないため見送り。過去分を見たくなったら足す。
- C 案（同じ作業を 2 回実行して実測）は、費用が 2 倍で普段の使い方を測れないため見送り。

## 仕組み

1. **記録（`turn.step`）**: メインのリクエスト（`agentId` がないもの）の結果の `usage` から、応答したモデルと、入力・出力・キャッシュ読み込み・キャッシュ書き込みのトークン数を足し込む。subagent は、どちらの方式でも同じなので数えない。
2. **分類の費用（`prompt.submit`）**: `$.model.complete` の結果の `usage` を、実際の側にだけ足す。
3. **基準のトークン数**: 入力・出力は実際と同じ数とする。キャッシュだけ補正する。
   - 直前のメインのリクエストとモデルが変わったリクエストでは、キャッシュ書き込みのうち、直前のリクエストまでにあった分（`min(書き込み, max(0, 直前のプロンプト全体 - 今回の読み込み))`）は、「基準のモデルなら読み込みで済んだ」として、基準の側では読み込みに移す。
   - プロンプト全体 = 入力 + キャッシュ読み込み + キャッシュ書き込み。
4. **料金**: 単価表をコードに持つ（下表、2026-11-03 時点、Anthropic 公式 API の価格）。キャッシュ書き込みは、5 分と 1 時間の内訳が `usage` にないため、両側とも 1 時間（2 倍）で計算する。Claude Code はほとんど 1 時間で書いており、このセッションの Fable の集計（約 5.47 ドル）とも一致した。
   - 単価表にないモデルは計算から外し、その旨を表示する。
5. **保存**: セッションごとに `$.store` のキー `savings:<セッション ID>` に保存し、累計は表示のときに足し合わせる（レビューを受けて変更。1 つのキーを全セッションで書き換えると、同時に使ったときに加算が消えるため）。トークン数だけを保存し、料金は表示のたびに計算するので、単価表を直せば過去の分にも反映される。
6. **表示**: スラッシュコマンド `/model-router:savings [基準のモデル]`。既定は `opus`。このセッションと累計について、実際の料金、基準の料金、差額と割合、モデルごとのトークン数、分類の費用を出す。末尾に「effort の差は含まない」「キャッシュは補正した推定」と注記する。

| モデル | 入力 | 出力 | キャッシュ読み込み | キャッシュ書き込み（1 時間） |
|--|--|--|--|--|
| Opus 5.5 | 4.00 | 20.00 | 0.20 | 8.00 |
| Sonnet 5.5 | 2.00 | 10.00 | 0.10 | 4.00 |
| Fable 5.2 | 8.00 | 40.00 | 0.20 | 16.00 |
| Haiku 5.5 | 0.10 | 0.50 | 0.01 | 0.20 |

（単位: ドル / 100 万トークン。Haiku のキャッシュ読み込みは資料に明記がなく、0.1 倍とした私の判断）

## 実装する人に任せること

- 表示の細かな書式（表か箇条書きか、小数の桁）。
- 累計をリセットする手段は、今は作らない（必要なら `$.store` のキーを消すコマンドを足す）。

## テスト

`claude plugin test` に足す: 切り替えのないリクエストは補正しない、切り替えたリクエストは書き込みを読み込みに移す、subagent は数えない、分類の費用は実際の側だけに入る、累計が `$.store` に残る、単価表にないモデルは除外される。
