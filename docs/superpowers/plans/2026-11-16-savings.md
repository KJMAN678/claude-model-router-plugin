# 削減額の確認機能 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 実際の利用と、基準のモデルだけで動かした場合の、トークン数と料金の差を `/savings` コマンドで表示する。

**Architecture:** 計算は副作用のない関数として `hooks/savings.ts` に置く。`hooks/register.ts` は、`turn.step` と分類の結果から利用量を記録し、`$.store` に累計し、コマンドで表示するだけ。

**Tech Stack:** Claude Code mod（TypeScript、`claude-code` の型）、`claude plugin test`

**Spec:** [docs/superpowers/specs/2026-11-16-savings-design.md](../specs/2026-11-16-savings-design.md)

## Global Constraints

- 単価（ドル / 100 万トークン、入力・出力・キャッシュ読み込み・キャッシュ書き込み）: opus 4.00 / 20.00 / 0.20 / 8.00、sonnet 2.00 / 10.00 / 0.10 / 4.00、fable 8.00 / 40.00 / 0.20 / 16.00、haiku 0.10 / 0.50 / 0.01 / 0.20。キャッシュ書き込みは 1 時間の単価で両側とも計算する。
- モデルの判別は、応答したモデル ID（`claude-opus-5-5` など）に `opus` / `sonnet` / `fable` / `haiku` が含まれるかで行う。どれも含まないモデルは計算から外し、表示で件数を伝える。
- 数えるのはメインのリクエストだけ（`turn.step` の `e.agentId` がないもの）。
- 分類の Haiku の利用量は、実際の側にだけ足す。
- 基準の effort は計算に使わない。表示の末尾に「effort の差は含まない」「キャッシュは補正した推定」と出す。
- 累計は `$.store` のキー `savings-totals`。このセッションの分はモジュール変数。
- コマンド名は `savings`、引数は基準のモデル（`opus` / `sonnet` / `fable` / `haiku`）、省略時は `opus`。
- 新しい依存は増やさない。

## Review Focus

1. **分類が `$.model.complete` 以外の経路で決まったターン（モデルの明示）** — 分類を呼んでいないので、分類の費用は 0 のままであるべき。→ Task 2 のテスト `explicit model adds no classifier usage`。
2. **`usage` が null の結果（中断、API エラー）** — 何も足さず、例外も出さないべき。→ Task 2 のテスト `a step without usage records nothing`。
3. **最初のリクエスト（直前のモデルがない）** — 切り替えとみなさず、補正しないべき。→ Task 1 のテスト `first request is not a switch`。
4. **書き込みが、直前のプロンプトより大きい** — 補正は直前のプロンプト分までで、残りは書き込みのまま。→ Task 1 のテスト `adjustment is capped by previous prompt`。
5. **`$.store` に、形の違う値（古い版の値や壊れた値）が入っている** — 空の累計として扱い、上書きできるべき。→ Task 2 のテスト `unreadable store starts from zero`。

### Task 1: 計算の関数（`hooks/savings.ts`）

**Files:**
- Create: `hooks/savings.ts`
- Test: `hooks/savings.test.ts`

**Interfaces:**
- Produces:
  - `type Tokens = { input: number; output: number; cacheRead: number; cacheWrite: number }`
  - `type Totals = { actual: Record<string, Tokens>; baseline: Tokens; classifier: Tokens; requests: number; unpriced: number; prevModel?: string; prevPrompt?: number }`（`actual` のキーはモデルの種類 `opus` など）
  - `emptyTotals(): Totals`
  - `family(modelId: string): 'opus' | 'sonnet' | 'fable' | 'haiku' | undefined`
  - `recordStep(t: Totals, modelId: string, u: { input_tokens: number; output_tokens: number; cache_read_input_tokens: number; cache_creation_input_tokens: number }): Totals`（新しい値を返す。元の `t` は変えない）
  - `recordClassifier(t: Totals, u: 同上): Totals`
  - `cost(tokens: Tokens, fam: string): number`（ドル）
  - `report(session: Totals, total: Totals, baselineFamily: string): string`（コマンドに出す文章）
  - `parseTotals(value: unknown): Totals`（形が合わなければ `emptyTotals()`）

- [ ] **Step 1: 失敗するテストを書く**（`hooks/savings.test.ts`、`claude-code/testing` の `test` と `expect`。`$` と `on` は使わない）

```ts
const U = (i: number, o: number, r: number, w: number) =>
  ({ input_tokens: i, output_tokens: o, cache_read_input_tokens: r, cache_creation_input_tokens: w })

test('cost uses the 1h write price', () => {
  expect(cost({ input: 1e6, output: 1e6, cacheRead: 1e6, cacheWrite: 1e6 }, 'opus')).toBe(4 + 20 + 0.2 + 8)
})
test('first request is not a switch', () => {
  const t = recordStep(emptyTotals(), 'claude-opus-5-5', U(10, 5, 0, 1000))
  expect(t.baseline).toEqual({ input: 10, output: 5, cacheRead: 0, cacheWrite: 1000 })
})
test('same model keeps cache as is', () => {
  let t = recordStep(emptyTotals(), 'claude-opus-5-5', U(10, 5, 0, 1000))
  t = recordStep(t, 'claude-opus-5-5', U(10, 5, 1000, 200))
  expect(t.baseline.cacheRead).toBe(1000)
  expect(t.baseline.cacheWrite).toBe(1200)
})
test('a switch moves prior prefix from write to read', () => {
  let t = recordStep(emptyTotals(), 'claude-opus-5-5', U(10, 5, 0, 1000))   // prompt 1010
  t = recordStep(t, 'claude-sonnet-5-5', U(10, 5, 0, 1300))                  // 1010 moved
  expect(t.baseline.cacheRead).toBe(1010)
  expect(t.baseline.cacheWrite).toBe(1000 + 290)
  expect(t.actual.sonnet).toEqual({ input: 10, output: 5, cacheRead: 0, cacheWrite: 1300 })
})
test('adjustment is capped by previous prompt', () => {
  let t = recordStep(emptyTotals(), 'claude-opus-5-5', U(0, 0, 0, 100))
  t = recordStep(t, 'claude-fable-5-2', U(0, 0, 0, 5000))
  expect(t.baseline.cacheRead).toBe(100)
  expect(t.baseline.cacheWrite).toBe(100 + 4900)
})
test('unknown model is counted as unpriced', () => {
  const t = recordStep(emptyTotals(), 'claude-x-1', U(10, 5, 0, 0))
  expect(t.unpriced).toBe(1)
  expect(t.actual).toEqual({})
})
test('classifier usage is actual only', () => {
  const t = recordClassifier(emptyTotals(), U(100, 2, 0, 0))
  expect(t.classifier.input).toBe(100)
  expect(t.baseline.input).toBe(0)
})
test('report names baseline, saving and caveats', () => {
  const t = recordStep(emptyTotals(), 'claude-sonnet-5-5', U(1e6, 0, 0, 0))
  const s = report(t, t, 'opus')
  expect(s).toContain('Opus')
  expect(s).toContain('2.00')        // 基準 4.00 - 実際 2.00 の差
  expect(s).toContain('effort の差は含まない')
  expect(s).toContain('キャッシュは補正した推定')
})
test('parseTotals rejects a wrong shape', () => {
  expect(parseTotals({ actual: 1 })).toEqual(emptyTotals())
  expect(parseTotals(undefined)).toEqual(emptyTotals())
})
```

- [ ] **Step 3: `hooks/savings.ts` を実装する**

補正の式（設計書の 3）: 切り替えたリクエストでは `moved = min(w, max(0, prevPrompt - r))` を、基準の側で書き込みから読み込みに移す。`prevPrompt` は直前のリクエストの `input + cacheRead + cacheWrite`（実際の値）、`prevModel` はモデル ID。単価表にないモデルは `unpriced` を 1 増やし、`actual` にも `baseline` にも足さず、`prevModel` / `prevPrompt` だけ更新する。`report` の差額と割合は「基準の料金 −（実際の料金 + 分類の料金）」で、セッションと累計の 2 段。金額は小数 2 桁のドル表記。

### Task 2: 記録・保存・コマンド（`hooks/register.ts`）

**Files:**
- Modify: `hooks/register.ts`（`prompt.submit` の分類部分、`turn.step`、`session.start` と `command.run` を追加）
- Test: `hooks/register.test.ts`

**Interfaces:**
- Consumes: Task 1 の `emptyTotals`、`recordStep`、`recordClassifier`、`parseTotals`、`report`、`family`。
- Produces: コマンド `savings`（`$.command.register({ name: 'savings', description: '…' })`、`session.start` で登録）。`$.store` キー `savings-totals`。

- [ ] **Step 1: 失敗するテストを書く**（既存の `setup` に倣い、`on('turn.step', …)` が `usage` 付きの結果を返す形を足す。`on('store.get' / 'store.set')` で `$.store` を差し替える）

テスト名と確かめること:
- `a main step is recorded and saved`: `usage` 付きの `turn.step` を 1 回流した後、`store.set` に `savings-totals` が渡り、`actual.sonnet.input` が渡した値
- `a subagent step is not recorded`: `agentId` 付きでは `store.set` が呼ばれない
- `a step without usage records nothing`: `usage: null` では `store.set` が呼ばれず、例外もない
- `classifier usage is recorded`: 分類で `isAnswered: true, usage: …` を返すと、`classifier.input` が増える
- `explicit model adds no classifier usage`: 「Fable で」のプロンプトでは `classifier` が 0 のまま
- `unreadable store starts from zero`: `store.get` が `{ actual: 1 }` を返しても、記録後の `requests` が 1
- `savings command reports against opus by default`: `command.run` に `{ command: 'savings', args: '' }` を流すと、返る `text` に `Opus` と `effort の差は含まない` が含まれる
- `savings command takes a baseline`: `args: 'sonnet'` で `Sonnet` を含む

- [ ] **Step 3: `register.ts` に組み込む**

- `turn.step`: `const r = yield* next(...)` で結果を受け、`e.agentId` がなく `r.usage` があれば、セッションの `Totals` と、`$.store` から読んだ累計（`parseTotals`）の両方に `recordStep` し、累計を `$.store.set('savings-totals', …)` で書く。保存の失敗は握りつぶす（切り替えを止めない）。結果 `r` はそのまま返す。
- 分類: `$.model.complete` の結果が `isAnswered` のとき、`r.usage` を `recordClassifier` で両方に足し、保存する。
- `session.start` で `savings` を登録し、`command.run`（matcher `{ command: 'savings' }`）で `args.trim()` を基準（`family` で正規化、空・不明なら `opus`）として `report` の文章を `{ text }` で返す。
- ponytail: セッションの分はモジュール変数なので、mod の再読み込みで 0 に戻る（累計は残る）。コメントに残す。
